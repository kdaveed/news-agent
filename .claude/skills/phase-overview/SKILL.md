# Phase overviews

Before editing a phase overview, read `phases/phase-1-event-source-discovery/1-overview.md` from the repository root. It is the reference for brevity, tone and structure.

- Tell the story of how the user directed the work: requests, important agent suggestions, challenges, corrections and decisions.
- Use short `@me`, `@agent` and `@consideration` entries, grouped under simple numbered headings like Phase 1.
- Keep only the exchanges that changed the direction or explain the result. Combine repetitive exchanges.
- Match the length and detail of a comparable Phase 1 section, rather than retelling the whole conversation.
- Leave schemas, configuration, commands, implementation plans and detailed evidence in thread documents or artifacts. Link only when useful.
- Distinguish proposals, user decisions and completed checks. Do not invent user reasoning or present agent suggestions as accepted decisions.
- Preserve other threads' sections unless asked to revise them.

Before finishing, compare the new section with Phase 1 and remove details that do not explain a decision or correction. The overview is a concise process narrative, not a technical specification or transcript.
